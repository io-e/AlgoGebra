## 1. Purpose

Define what AlgoGebra persists for a student's session so that:
- A session can be **saved and resumed** (desktop: close/reopen, web: refresh)
- A session can be **submitted** to WIMS for grading (connected mode, Phase 2)
- The teacher or LMS can **review** what the student did

## 2. Session state model

```java
public class SessionState {
    // Identity
    String sessionId;          // UUID, generated at session start
    String courseFile;          // path to course.json
    String schemaVersion;      // "1.0"
    
    // Variant (GAP-6)
    int variantIndex;          // index into course.json variants[]
    Map<String, String> resolvedVariables;  // variable → value for this variant
    
    // Progress
    String currentStepId;      // step the student is viewing
    Map<String, StepState> stepStates;  // stepId → state
    
    // GeoGebra construction
    byte[] ggbState;           // GeoGebra .ggb binary (api.getBase64())
    
    // Timing
    Instant startedAt;
    Instant lastSavedAt;
    Duration totalActiveTime;  // excludes pauses
}
```

### 2.1 Per-step state

```java
public class StepState {
    enum Status { NOT_VISITED, VISITED, ATTEMPTED, PASSED, FAILED }
    
    Status status;
    List<AttemptRecord> attempts;   // max 10 per step
    ComputeResultRecord lastCompute;
    Instant firstVisitedAt;
    Instant lastAttemptAt;
}
```

### 2.2 Attempt record

```java
public class AttemptRecord {
    int attemptNumber;          // 1-based
    Map<String, String> answers; // variable → student's answer
    CheckResult result;         // pass/fail + feedback
    Instant attemptedAt;
    Duration computeTime;       // engine wall-clock time
}
```

## 3. Serialization format

Session state is serialized as a **JSON file** alongside the `.ggb` construction:

```
session_<uuid>/
├── session.json          ← session state (this spec)
├── construction.ggb      ← GeoGebra state (binary)
└── compute_cache/        ← cached engine results (optional)
    ├── step_1_pari.txt
    └── step_3_gnuplot.png
```

### 3.2 Step ID convention

Step IDs are path-based: `<chapter_index>.<step_index>[.<child_index>]*`. Example: `chap1.step2.sub1`. Generated by the CourseModel loader from the tree structure. Stable across sessions for the same course.json.

## 4. Save/resume lifecycle

### 4.1 Auto-save

| Event | Action |
|---|---|
| Step navigation (click another step) | Save current step state + GeoGebra construction |
| Check attempt | Save attempt record |
| Timer (every 60s of active time) | Save construction snapshot |
| Application close | Full save |

### 4.2 Resume

1. Load `session.json` — validate `schemaVersion`, `courseFile` exists
2. Load `construction.ggb` via `api.setBase64()`
3. Navigate to `currentStepId`
4. Restore step states (visited/attempted/passed/failed badges in tree)
5. If `compute_cache/` exists, display cached results without re-running engines

### 4.3 Storage location

| Platform | Path |
|---|---|
| Desktop RCP | `<workspace>/sessions/<sessionId>/` |
| Web (Phase 2+) | `localStorage` or IndexedDB (TBD) |

## 5. Submission contract (Phase 2 — connected mode)

### 5.1 What gets submitted

When the student submits (connected mode), AlgoGebra sends:

```json
{
  "sessionId": "...",
  "courseFile": "...",
  "variantIndex": 7,
  "answers": {
    "chap1.step1.ans1": "2x+3",
    "chap1.step2.ans1": "x^2+3"
  },
  "metadata": {
    "startedAt": "2026-11-04T10:00:00Z",
    "submittedAt": "2026-11-04T10:15:30Z",
    "totalActiveTime": "PT12M30S",
    "attemptCounts": { "chap1.step1": 1, "chap1.step2": 1 }
  }
}
```

The submission contains **only the answers** and metadata. The GeoGebra construction is not submitted (too large, and WIMS doesn't process it). Check results are not submitted — WIMS re-evaluates.

### 5.2 Idempotency (S-03)

Each submission carries `sessionId` + `submissionSequence` (monotonic counter). If WIMS receives a duplicate `(sessionId, submissionSequence)`, it returns the cached result without re-evaluating.

### 5.3 Retry

On network failure, AlgoGebra retries with the same `submissionSequence`. Maximum 3 retries with exponential backoff (1s, 2s, 4s). After 3 failures, the student sees "Submission failed — your answers are saved locally" and can retry manually.

## 6. Privacy and data retention

| Data | Stored where | Retention |
|---|---|---|
| Session state (local) | Student's machine | Until student deletes or course ends |
| Submission (connected) | WIMS server class directory | WIMS class retention policy (teacher-controlled) |
| GeoGebra construction | Student's machine only | Never submitted to WIMS |
| Compute cache | Student's machine only | Cleared on new variant or session reset |

No telemetry. No analytics. No data leaves the student's machine in offline mode.
