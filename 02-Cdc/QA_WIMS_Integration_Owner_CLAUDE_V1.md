## Q-W4 — Grading contract: what crosses the wire?

**Question:** What does AlgoGebra send? What does WIMS return? Retry semantics?

**Answer (AlgoGebra → WIMS):** Not only final answers. AlgoGebra sends **computation help requests** as well — the student can ask WIMS/engines for intermediate calculation assistance, explanations, and exploration, not just submit final answers for grading.

**Answer (WIMS → AlgoGebra):** Structured object with per-answer detail (not just a single score). This includes: per-answer correctness, partial credit, feedback text, and hints when the teacher has configured them.

**Answer (Retry / idempotency):** *Needs clarification — see explanation below.*

### Explanation needed: S-03 idempotency

The V2 scenario S-03 says: "Retry the same idempotency key → one grade record." This is a technical safeguard for connected mode:

- **Problem it solves:** if the network drops during submission, the student clicks "Submit" again. Without protection, WIMS could record two grade entries for the same attempt.
- **Idempotency key:** a unique ID (e.g. UUID) generated by AlgoGebra for each submission attempt. If WIMS receives the same key twice, it returns the existing grade instead of creating a duplicate.
- **For offline mode (our MVP):** this is simpler — the local scorer is deterministic, and there is no network retry issue. The idempotency contract matters when connected mode lands (Phase 2).

**Owner action:** no decision needed now. The CDC will note S-03 as a Phase 2 requirement for connected mode.

## Q-W5 — Teacher authoring scope

**Question:** Teacher creates in WIMS only (read-only client)? AlgoGebra includes authoring? Middle ground?

**Answer:** The teacher creates **OEF exercises** and **GeoGebra (.ggb) constructions**. When the student encounters an error or needs explanation, WIMS/AlgoGebra provides help — the communication is bidirectional, not just grading.

**Implication:** The teacher authors in two tools:
1. **OEF files** (WIMS exercise format) — using the existing WIMS authoring workflow or a text editor.
2. **GeoGebra constructions** (`.ggb` files) — using standard GeoGebra.

AlgoGebra is not an OEF editor. But AlgoGebra must be able to **display exercise instructions**, **accept student interaction with the GeoGebra construction**, **request computation help from engines**, and **present structured feedback** from the exercise evaluation.

The "help" flow: when a student makes an error, AlgoGebra can call the engine (locally or via WIMS) to provide step-by-step calculation assistance, not just a pass/fail grade. This is **formative feedback**, distinct from the summative grade.

## Q-W6 — Engine availability vs. WIMS server fallback

**Question:** Missing local engine = error or silent fallback to WIMS CGI?

**Answer:** Fallback to WIMS applies **only to interactive exploration** (computation help), not to grading.

**Implication:** Two rules coexist:
- **Grading (offline):** local engine must be present. Missing binary = error. No silent fallback. The student/teacher is told which engine is missing and how to install it.
- **Interactive exploration:** if the local engine is missing but a WIMS server is reachable, AlgoGebra **may** send the computation request to WIMS CGI as a convenience. This is a degraded mode, not a silent substitution — the UI indicates "remote computation" so the student knows.

This reconciles D-ENG-02 ("missing = error") with S-01 ("WIMS as remote compute"): the error rule applies to grading; the fallback applies to exploration only.

## Q-W7 — wims4win as local server

**Question:** Is wims4win the local WIMS server? Student machine or teacher/developer only?

**Answer:** Yes, wims4win is the local server. Yes, the student can use it — specifically:
- **CPGE students** (classes préparatoires) can run it on a Shadow PC (cloud gaming/workstation service).
- **Teachers** use it for test authoring and exercise validation.

**Implication:** wims4win is not developer-only. The CDC must assume it runs on student machines (possibly via Shadow PC) and on teacher machines. Install/config instructions and resource requirements matter.

### Explanation needed: "local wims4win = connected mode"

The question was asking whether running wims4win locally blurs the line between "connected" and "offline" modes:

- **Connected mode** (as defined in the CDC) means: AlgoGebra sends a submission over HTTP to a WIMS server, and WIMS returns a grade. The WIMS server does the grading.
- **Offline mode** means: AlgoGebra runs the engines directly (via `SubprocessEngine`), no WIMS server involved.

When wims4win runs on the same machine as AlgoGebra, technically it is "connected" (HTTP to localhost), but the student experience is "offline" (no internet needed, everything local).

**The distinction that matters for the CDC:**
- **Offline:** AlgoGebra calls `gp.exe` / `maxima` directly. No `wims.cgi` in the loop. Simpler, fewer moving parts. This is the MVP.
- **Local-connected:** AlgoGebra sends HTTP to `localhost:port/wims/wims.cgi`. WIMS runs its own engine instances. More faithful to the WIMS grading model (same scorer as institutional deployment), but requires wims4win running as a service.

The MVP is offline. Local-connected is a natural Phase 2 stepping stone before institutional-connected (remote server).

## Q-W8 — Scope boundary with the course tree

**Question:** WIMS CDC covers protocol only, or the full exercise lifecycle?

**Answer:** Yes, use the course tree. The WIMS CDC covers **the protocol and engine integration**. Exercise navigation, loading, and presentation are the course tree's responsibility.

**Implication:** The WIMS CDC specifies:
- Engine subprocess contracts (already in `Cdc_External_Engines`)
- WIMS CGI submission/response protocol (Phase 2)
- Exercise evaluation contract (what the engine receives, what it returns)
- Formative feedback contract (help/explanation flow)

The course tree CDC specifies:
- Loading OEF/course.json
- Presenting exercise steps to the student
- Collecting student input from the GeoGebra construction
- Displaying grades and feedback from the evaluation contract

The boundary: **the course tree calls the evaluation contract; the WIMS CDC defines that contract.**
